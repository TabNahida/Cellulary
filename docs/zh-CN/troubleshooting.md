# 故障排查

[文档目录](README.md) · [English](../troubleshooting.md)

先记录型号、固件、失败命令及脱敏响应。某项功能不可用时，模块本身仍可能在线。分享日志前移除电话号码、短信正文、SIM 标识和设备标识。

## AT 端口被占用或找不到

用 `cellulary ports` 查找 AT 接口，诊断、下载和 Modem 接口不能互换。在另一个进程打开端口前，先停止 Cellulary Web 服务、串口终端及其他客户端。切换 USB 插口或驱动后重新枚举，原端口名可能已失效。

## EC801E 短信失败

已下载 E AT V1.3 第 95 页明确排除 EC801E 短信。检查实际固件的 `AT+CMGF=?` 响应；命令被拒绝或没有 PDU 模式应显示不支持，而非空收件箱。实测固件结果见[硬件验证](hardware-validation.md)。

支持 PDU 的固件应使用 `CMGF=0` 配合数字 `CMGL=4` 列出全部短信，`CMGL="ALL"` 属于文本模式。不要不断重试不支持的模式或发送；部分短信已经提交时，须保留提交引用，自动重试可能造成重复短信。

## SIM 没有显示本机号码

`CNUM` 读取 SIM 保存的数据。有的 SIM 返回号码，有的只返回 `OK`；后者表示未知，不妨碍网络注册或数据服务。`CPBS="ON"` 并非所有固件都支持，不是通用修复办法。不要从 IMSI/ICCID 推断号码，也不要为了显示字段而改写 SIM 电话本。

## 模块已连接，电脑却不能上网

逐层检查：

1. SIM 就绪、LTE 已注册，并区分漫游状态。
2. PDP 上下文及模块分配地址。
3. 支持的 RNDIS/ECM 固件上 `QNETDEVCTL?` 的状态，或系统枚举的 MBN 接口。
4. 正确主机网卡的 DHCP 地址与网关；APIPA/链路本地地址不是蜂窝网租约。
5. 路由与 DNS，再通过绑定该网卡的请求验证实际出口。

普通浏览器请求可能走其他网络，不能证明所选模块可用。应通过 USB 父设备关联 AT 端口与网卡；友好名称或 MAC 地址可能不足以区分。

多台 EC801E 可能使用相同 MAC。无卡模块获得 DHCP 租约，而已注册模块只有 APIPA 时，应检查主机网卡对应关系，不能直接归咎于 LTE 频段。释放/更新租约必须指向已确认的网卡，整体释放会影响其他连接。参阅[带日期的恢复证据](hardware-validation.md)。

长期多 SIM 部署应依据适用固件资料研究每模块唯一 MAC；这类配置可能持久化并需要重启。发现设备流程及本次单次恢复均不会自动实施。

## 通话没有声音

通话状态和音频传输分开。确认语音固件、SIM/运营商服务、需要的 VoLTE 配置，以及载板模拟/PCM/UAC 音频链路。管理台不传输浏览器麦克风/扬声器音频，本项目没有验证 EC801E 语音路径。

## GNSS 不可用或尚未定位

当前驱动没有为 EC200A-EU、EC801E 声明有资料支持的 GNSS 路径。EC25 协议实现仍需验证具体接收器变体与硬件。支持接收器时，应区分关闭和等待定位，实际位置还依赖天线及信号条件。

用 `gnss_status()` 或 `gnss_location()` 查看支持、接收器和定位状态。开启/关闭为显式操作，不应在打开页面时自动执行。

## Web 写请求被拒绝

从本地地址打开管理台，让它取得当前会话令牌。脚本调用应查看最新 API 结构并遵守会话要求，不要为解决旧会话而删除来源/Host 检查。旧客户端仍占端口时，停止并重启服务。
